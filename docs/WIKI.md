# «Рядом»: простое описание проекта

Эта страница объясняет проект человеку без опыта программирования. «Рядом» — доска для идей: на ней можно размещать заметки, текст, фигуры, рисунки, изображения и документы.

## Как запустить

Нужен установленный Docker Desktop или Docker Engine с Compose v2. В папке проекта выполните:

```sh
./start-docker.sh
```

Скрипт сам создаёт локальные секреты, запускает все части проекта и открывает доску по адресу `http://127.0.0.1:4173`. База данных и файлы сохраняются даже после остановки контейнеров.

Соседний C++-проект и отдельный C++-сервер для работы не нужны.

## Что происходит при работе

У проекта есть две основные части:

1. **Фронтенд** — страница, которую видит пользователь в браузере.
2. **Бекенд** — серверная часть, которая отвечает за аккаунты, серверные доски и файлы.

Когда пользователь просто рисует или пишет, изменения сохраняются в браузере. Когда он входит в аккаунт и выбирает «Сохранить новый снимок», браузер отправляет копию доски и оригиналы файлов на бекенд.

## Фронтенд

Фронтенд — это сама веб-страница с полотном и кнопками.

### Что умеет фронтенд

- добавлять стикеры, текст, прямоугольники и свободные линии;
- перемещать и изменять размеры объектов;
- отменять и возвращать действия;
- добавлять PNG, JPEG, WebP, GIF, PDF, Office и текстовые файлы;
- сохранять доску в браузере и восстанавливать её после перезагрузки;
- экспортировать доску вместе с вложениями в файл `.ryadom`;
- синхронизировать изменения между вкладками одного браузера;
- входить в аккаунт, создавать серверный снимок и загружать его обратно.

### Где хранятся локальные изменения

Браузер использует **IndexedDB** — встроенное локальное хранилище. Файлы лежат там как оригинальные двоичные данные, поэтому картинка после перезагрузки не превращается в пустой блок.

Для связи между открытыми вкладками используется **BroadcastChannel**. Это позволяет двум вкладкам одного браузера видеть рисунки и изменения друг друга.

Обычное редактирование сейчас остаётся локальным. Серверные доски, операции и WebSocket уже реализованы в бекенде, но полноценное редактирование одной доски разными устройствами ещё не подключено к основному полотну.

### Стек фронтенда и причины выбора

| Часть | Что используется | Почему |
| --- | --- | --- |
| Интерфейс | HTML, CSS, JavaScript | Не нужен тяжёлый сборщик и проще понять исходный код. |
| Локальное хранение | IndexedDB | Подходит для больших файлов и переживает перезагрузку страницы. |
| Связь вкладок | BroadcastChannel | Работает в браузере без отдельного сервера. |
| Раздача страницы | Node.js | Маленький локальный сервер и прокси к API. |
| Серверные запросы | `fetch` к `/api/v1/...` | Запросы идут через один адрес, поэтому браузеру не нужны специальные разрешения. |

## Бекенд

Бекенд — это набор сервисов в Docker Compose.

| Сервис | Простое объяснение |
| --- | --- |
| `web` | Отдаёт браузеру фронтенд и аккуратно проксирует запросы к API. |
| `api` | Python-сервер с правилами аккаунтов, досок, операций и файлов. |
| `db` | PostgreSQL — постоянная база данных. |
| `migrate` | Один раз применяет SQL-изменения, чтобы создать или обновить таблицы. |

### Что хранит бекенд

- аккаунты, роли и активность пользователей;
- безопасные хэши паролей и сессии входа;
- серверные доски, участников и приглашения;
- объекты доски и историю операций;
- изображения и документы в отдельном Docker volume;
- журналы запросов без паролей, токенов и содержимого файлов.

Сервер проверяет права на каждом запросе. Владелец доски может переименовывать её, приглашать и удалять участников. Администратор может просматривать пользователей, менять роль и отключать аккаунты. Последнего активного администратора отключить нельзя.

### Как сохраняется файл

1. Браузер отправляет файл на сервер.
2. Сервер проверяет размер, расширение и настоящую сигнатуру файла.
3. Файл сначала записывается во временное место и только после успешной проверки становится доступным.
4. В базе сохраняются имя, тип, размер, контрольная сумма и связь файла с объектом доски.
5. Скачать файл можно только с действующим входом и правом доступа к доске.

### Стек бекенда и причины выбора

| Часть | Что используется | Почему |
| --- | --- | --- |
| Язык | Python 3.12 | Быстро читается и подходит для небольшого API. |
| HTTP API | FastAPI и Uvicorn | Удобные маршруты, автоматическая OpenAPI-документация и хорошая поддержка async-запросов. |
| Проверка данных | Pydantic | Ошибочные объекты и значения отбрасываются до записи в базу. |
| Доступ к БД | `psycopg` | Прямой параметризованный доступ к PostgreSQL без лишнего ORM-слоя. |
| База | PostgreSQL 16 | Надёжные транзакции, блокировки и внешние связи для совместных операций. |
| Зависимости Python | `uv` и lock-файл | Одинаковые версии пакетов у разработчика и в Docker; системный Python не изменяется. |
| Запуск | Docker Compose | База, API и web запускаются одинаково на разных компьютерах. |

## Тесты

Тесты разделены по уровню, чтобы отдельно проверять маленькие функции, API и настоящий пользовательский сценарий.

### Тесты фронтенда и Node.js

- `npm test` проверяет модель объектов, координаты, масштаб, импорт/экспорт, ограничения файлов и клиент Python API.
- `node scripts/proxy-test.mjs` проверяет маршруты прокси, заголовки авторизации, multipart-загрузку, idempotency key, WebSocket-туннель, CSP и ответ при недоступном API.
- `node scripts/board-test.mjs` запускает браузерный сценарий. Проверяются рисование, текст, отмена/повтор, перезагрузка, XSS-защита, PNG/PDF, две вкладки, экспорт/импорт, серверный снимок, загрузка шести файлов, восстановление изображения, вход и выход.

### Тесты Python-бекенда

- модели всех шести типов объектов: `sticky`, `text`, `shape`, `stroke`, `image`, `file`;
- проверка координат, размеров, текста, цветов и ссылок на вложения;
- аккаунты, вход, refresh, logout и отзыв сессий;
- операции доски, ревизии, конфликты, повтор операций и приглашения;
- PostgreSQL-запросы и изоляция пользователей;
- загрузка, сигнатуры, контрольные суммы, атомарное сохранение и скачивание файлов;
- изображения, документы, лимиты размера и квоты доски;
- WebSocket-ticket и временные события;
- логирование без паролей и токенов;
- список пользователей, роли, отключение аккаунтов и защита последнего администратора;
- лимиты размера HTTP-запросов и OpenAPI-маршруты.

Команды:

```sh
npm test
cd backend && uv run --locked --group dev python -m pytest
./scripts/test-backend.sh
```

Последняя команда поднимает отдельную временную PostgreSQL и запускает интеграционные тесты. На машине без Docker Compose такие тесты помечаются как пропущенные, а локальные unit-тесты всё равно выполняются.

## Короткий словарь

- **Фронтенд** — всё, что открыто в браузере.
- **Бекенд** — серверная часть за браузером.
- **API** — понятные адреса, по которым браузер просит сервер выполнить действие.
- **База данных** — организованное постоянное хранилище записей.
- **Docker** — изолированные контейнеры, в которых запускаются части проекта.
- **Снимок** — отдельная серверная копия текущей доски.
- **IndexedDB** — встроенная база данных браузера.
