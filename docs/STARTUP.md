# Один скрипт запуска

Из папки `naroshno`:

```sh
./frondent/start.mjs
```

Или `node frondent/start.mjs`. Из папки `frondent` доступна та же команда через `npm run start:all`.

Скрипт запускает C++ API и фронтенд. Открыть `http://127.0.0.1:4173`; API доступен на `http://127.0.0.1:5555`. Ctrl+C останавливает оба процесса. Если один сервер неожиданно завершается, второй также останавливается. Скрипт не занимает уже используемые порты и не завершает чужие процессы.

**Сейчас фронтенд сохраняет заметки в браузере и не вызывает API.** Сам по себе запуск двух серверов не добавляет авторизацию, синхронизацию или совместное редактирование.

## Запустить доступный сейчас редактор

```sh
./frondent/start.mjs --frontend
```

В этом режиме не нужны C++-библиотеки и PostgreSQL. Это тот же скрипт, а не отдельный способ установки. Прежний `npm start` также остаётся доступен.

## Почему готовый бэкенд сейчас не запускается

Проверка `ldd todo_list_cpp/build/petty_plusik` показала отсутствующие библиотеки:

- `libpq.so.5`
- `libsodium.so.23`
- `libyaml-cpp.so.0.8`
- `libmariadb.so.3`
- `libhiredis.so.1.1.0`

Нужна сборка, совместимая с установленными библиотеками, или эти зависимости с подходящими ABI. Подменять отсутствующие версии символическими ссылками нельзя. Скрипт выводит актуальный список и завершает запуск до старта серверов. Скачивание, установка пакетов и автоматическая сборка не выполняются: CMake проекта содержит сетевой FetchContent для jwt-cpp.

Также нужна уже запущенная PostgreSQL на `127.0.0.1:5432`, база `notes_db`, пользователь и пароль из `todo_list_cpp/config.json`, а также схема таблиц из моделей (`users`, `notes`, `users_notes`, `refresh_tokens`). Пароль в документацию не копируется. SQL-миграции в проекте не найдены; их должен предоставить бэкендер. Скрипт проверяет TCP-доступность PostgreSQL, но не подтверждает пароль, существование схемы или успешность API-запросов. Он не создаёт базу и не управляет системными службами.

**Передать бэкендеру:** предоставить совместимый исполняемый файл с зависимостями и инструкцию/миграции для подготовки PostgreSQL. После этого повторить ту же команду запуска. Задачи интеграции интерфейса описаны отдельно в `BACKEND_HANDOFF.md`.

## Конфигурация и параметры

```sh
PORT=4174 BACKEND_PORT=5556 ./frondent/start.mjs
BACKEND_BINARY=/абсолютный/путь/к/petty_plusik ./frondent/start.mjs
./frondent/start.mjs --help
```

Пути проекта вычисляются относительно самого скрипта, поэтому он работает из любой текущей папки. `BACKEND_BINARY` должен указывать на доверенную совместимую сборку с тем же контрактом конфигурации. Смена адреса/порта фронтенда меняет browser origin: локальные заметки со старого адреса автоматически не переносятся.

`main.cc` читает `../config.json` относительно рабочей папки. Чтобы не менять оригинал и не создавать логи в C++-проекте, скрипт создаёт `frondent/.runtime/session-*/config.json` и запускает бинарник из вложенной `work/`. В копии задаются loopback-адрес, выбранный порт, пустая статическая папка, локальные логи/загрузки и работа в foreground. Настройки базы и приложения берутся из оригинала.

Временный каталог имеет приватные права, конфигурация — `0600`. Он исключён из Git и удаляется после штатной остановки. После аварийного выключения или SIGKILL каталог может остаться; он содержит копию конфигурации с секретами и не должен публиковаться. Оригинальный `todo_list_cpp/config.json` не изменяется.

## Проверка

`node scripts/launcher-test.mjs` из `frondent` проверяет запуск двух процессов, остановку по SIGINT/SIGTERM, очистку конфигурации, занятый порт, ошибку дочернего процесса, произвольную рабочую папку и неверные параметры. Использует отдельный временный проект, тестовые серверы и имитацию проверки библиотек. Реальную БД и исходный бэкенд не трогает.

Проверки пройдены. Проверка настоящего бинарника корректно останавливается на перечисленных отсутствующих библиотеках; работа настоящего C++ API с PostgreSQL пока не подтверждена. Никакое ПО не устанавливалось.
